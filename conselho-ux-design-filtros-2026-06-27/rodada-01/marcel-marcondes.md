# Marcel Marcondes — Rodada 1

Vamos olhar isso com clareza, porque o que o CEO está descrevendo não são quatro problemas — são quatro sintomas de uma causa raiz só: o produto cresceu por inércia, não por design intencional.

O design "amador e tosco" não tem nada a ver com glassmorphism. Glassmorphism é cosmético. A causa raiz é que o produto foi construído de dentro para fora — o dev conhece os dados, então empilhou informação sem questionar a jornada do usuário. O gestor de marketing abre o dashboard e precisa resolver um problema de negócio, não navegar em uma estrutura de banco de dados com interface. Hierarquia visual é consequência de hierarquia de decisão. Se você não sabe o que o usuário precisa decidir primeiro, você vai colocar tudo na mesma altura visual. A pergunta que precisa ser respondida antes de qualquer pixel é: qual é a ação mais importante que o usuário faz nesta tela? Até responder isso, qualquer refinamento visual é maquiagem.

O filtro de campanhas Meta não funcionando é grave, mas não pelo bug em si — é grave pelo que revela. Esse produto tem usuários internos com dados reais, e a integração principal de tráfego pago não está funcionando de ponta a ponta. Qual é a métrica que move a agulha aqui? Performance de campanhas. E o filtro desta métrica não fecha. Isso não é dívida técnica, é dívida estratégica. Não escale o que não está maduro. Se esse produto fosse para um cliente externo hoje, essa falha seria o primeiro motivo de churn.

O que mais me incomoda nos filtros com itens inativos não é o volume de opções — é o que ele comunica sobre quem projetou o produto. Quando você mostra 50 campanhas e o usuário precisa achar as 3 relevantes, você transferiu o trabalho de análise para o usuário. Isso é o oposto de customer centricity. O sistema tem os dados do período selecionado, sabe quais campanhas têm investimento, sabe quais têm resultado. A curadoria deveria ser automática. Mostrar tudo é uma decisão preguiçosa disfarçada de "flexibilidade".

O bug de limpeza de leads me diz uma coisa só sobre maturidade do produto: não existe protocolo de operações destrutivas. Um botão que não faz nada silenciosamente não é um bug de RLS — é ausência de feedback loop. Produto maduro tem confirmação explícita, tem log de auditoria, tem reversibilidade ou ao menos rastreabilidade. O fato de ter sido resolvido com policies de DELETE é o começo, mas a pergunta real é: quantas outras operações críticas no produto têm o mesmo nível de governança zero? KPIs claros e accountability valem para o produto também, não só para a equipe.
