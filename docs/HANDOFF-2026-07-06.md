## 3. Riscos conhecidos (não são bugs — são limitações aceitas)

1. **Sincronização de agendamento depende da API do GHL estar correta.** Se o GHL tiver o dado errado do lado deles, o dashboard herda o erro — não tem como validar isso further sem acesso direto ao GHL.
2. **Detecção de cancelamento de appointment é heurística** (`supabase/functions/sync-appointment-dates/index.ts`, `isCanceledAppointment`) — verifica múltiplos nomes de campo possíveis. Um nome de campo novo/desconhecido no payload do GHL pode escapar dessa checagem.
3. **Janela de resync de 60 dias** (`ACTIVE_LOOKBACK_DAYS` em `sync-appointment-dates`) — oportunidades muito antigas só são revalidadas se nunca tiverem sido sincronizadas.
4. **Custo estimado de WhatsApp é uma aproximação** — usa `trigger_count` (contatos com a tag de disparo) como proxy do volume de mensagens realmente entregues. Não é reconciliação exata com a fatura da Meta.
