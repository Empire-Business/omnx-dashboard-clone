# Gary Vaynerchuk — Rodada 2: Embates

Escuta, Alex. Você disse "posicionamento interno do produto" e acertou na veia. Mas onde você errou é achar que a sidebar resolve o problema de empatia. Sidebar é para quem já sabe o que procura. O usuário que não sabe que existe painel de admin não vai olhar para a sidebar inferior — ele vai continuar perdido, vai ligar para o suporte, vai mandar mensagem no WhatsApp, vai reclamar no grupo. O componente visual precisa aparecer no contexto certo, na hora certa. Para o admin novo: no AppHub, em destaque, com linguagem de convite — não de configuração. "Personalize seu workspace" funciona melhor do que "Admin" porque faz a pessoa querer clicar.

Russell, você quase acertou com o funil de onboarding, mas você está tratando o admin como se fosse um lead de marketing. Ele não é. Ele é um usuário que já comprou, que já tem responsabilidade, e que está ocupado. A sequência linear que você propõe funciona no primeiro acesso — concordo 100%. Mas depois do primeiro acesso, o admin precisa encontrar as configurações de forma autônoma, sem depender de uma sequência guiada. Você resolve o problema do dia 1. Eu estou preocupado com o dia 30, quando o admin lembra que precisa ativar um novo app e não sabe mais onde está aquele fluxo.

Marcel, você mediu a métrica certa: tempo até primeira configuração. Mas eu adicionaria uma segunda: número de vezes que o admin abre um ticket de suporte perguntando "onde fica o controle de apps". Essa métrica diz mais sobre o custo real do problema do que qualquer NPS. Produto que precisa de suporte para ser navegado não é produto — é protótipo.
