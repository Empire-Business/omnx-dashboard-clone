# Alex Hormozi — Rodada 2: Embates

Gary, você está certo no diagnóstico mas errado na dose. "Empatia com o usuário novo" é a causa, sim — mas a solução não é apenas colocar um link na sidebar. O problema é de valor percebido escondido. Quando você oculta o controle de apps atrás de um ícone sem label, você está dizendo implicitamente ao admin que essa funcionalidade não é importante. E o admin acredita. Resultado: baixa adoção, baixa ativação, cliente que nunca experimenta o produto completo. Isso não é falha de interface — é falha de posicionamento interno do produto. Você pode resolver com design, mas a raiz é estratégica.

Russell, você trouxe a ideia mais interessante da rodada, mas pelo motivo errado. Você chama de "funil de onboarding do admin" o que na verdade é sequência de ativação — e são coisas diferentes. Onboarding implica que o admin é novo no sistema. Ativação significa que ele tem o poder nas mãos mas não sabe. O botão "Gerenciar Apps" no AppHub é uma boa ideia, mas não resolve o problema do admin que já passou pelo AppHub e está dentro de um app operacional sem saber como voltar para a configuração. Você precisa de ambos: entrada no AppHub E entrada persistente em qualquer contexto de uso.

Minha posição não muda: sidebar inferior com seção "Workspace" visível apenas para admins, dois links diretos (Usuários, Apps), separador visual limpo. Essa é a solução que maximiza utilidade sem poluir o espaço para SDRs. Grant tem razão que o produto está sendo tímido — mas a resposta não é botão vermelho gritando "ADMIN". A resposta é presença constante e elegante. O admin que precisa configurar o workspace às 22h no celular não tem tempo de procurar. Ele precisa que esteja lá.
