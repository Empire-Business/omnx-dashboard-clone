# Rodada 3 — Sandro San

Reconheço o argumento de Brunson em um ponto específico: o estado de primeiro acesso. Um workspace recém-criado sem nenhum sinal de "por onde começar" é um produto que abandona o usuário no momento mais crítico. Não é onboarding de lead — é redução de abandono. Aceito essa distinção.

O que não abro mão: governança e operação devem ter entradas visuais separadas. O admin que entra no sistema para ligar um app e o SDR que entra para ver seus leads devem sentir que estão em territórios diferentes. Misturar os dois no mesmo contexto visual cria a confusão que estamos tentando resolver. A solução não é apenas mostrar ou esconder items — é que o admin tenha um espaço que comunica autoridade e controle.

Cedo na implementação: aceito que no MVP isso seja resolvido com visibilidade condicional na sidebar (seção "Workspace" visível só para admins) e entrada no AppHub para primeiro acesso. A separação visual completa — página admin com layout próprio — pode vir depois. O que importa agora é que o admin encontre o controle em menos de 5 segundos. Fazemos isso primeiro, refinamos depois.
