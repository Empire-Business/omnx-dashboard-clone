# Sandro San — Rodada 1: Diagnóstico

Faz sentido para você que um sistema vendido como solução de gestão para times profissionais exija que o gestor descubra por acidente onde configurar seus próprios apps? Não faz. A causa raiz aqui é uma confusão de papéis na interface. Operação e governança estão misturadas. O admin usa o sistema para operar — ver leads, métricas, performance — mas também precisa governar o sistema — ativar módulos, gerenciar usuários, definir permissões. São dois modos completamente diferentes. Quando você coloca os controles de governança escondidos dentro da experiência de operação, você está dizendo implicitamente que governança é secundária. E o admin percebe isso, mesmo que inconscientemente.

A maior oportunidade desperdiçada é a percepção de controle. Em sistemas de alto valor, o admin precisa sentir que é soberano — que ele controla o que o time acessa, o que pode ser feito, como o workspace está configurado. Essa sensação de controle aumenta o valor percebido do produto. Quando ele não encontra onde configurar nada, o que ele sente? Impotência. E impotência é o oposto do que um sistema de gestão deveria provocar.

Minha primeira prioridade: separe governança de operação com uma entrada dedicada, sempre visível, sempre acessível, independente do app que o admin está usando. Não um dropdown. Uma seção na sidebar inferior ou um link fixo no header com ícone de engrenagem e label "Workspace". Soberano de verdade acessa seu painel de controle com um clique, sem caça ao tesouro. Pense grande: o admin que sente que controla o sistema defende o sistema. O admin perdido vira crítico.
