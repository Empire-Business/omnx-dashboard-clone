# Alex Hormozi — Rodada 1: Diagnóstico

Aqui está o problema: vocês construíram um painel de controle de sistema e esconderam atrás de um ícone de usuário que não diz nada. Não é um problema de UX sofisticado. É um problema de comunicação. O usuário tem que adivinhar que existe um painel de admin, descobrir que precisa clicar no ícone de usuário, e então descobrir que ali tem "Pessoas" e "Apps". Três passos de descoberta para algo que deveria ser óbvio. A causa raiz é simples: quem construiu pensou em funcionalidade, não em acesso. Funcionalidade sem acesso óbvio é funcionalidade que não existe.

A maior oportunidade sendo desperdiçada aqui é posicionamento de produto. Um painel de controle robusto, com controle granular de apps por workspace, é um diferencial real. Isso é o tipo de feature que justifica cobrar mais, que retém o cliente que cresce, que converte o admin em campeão interno da ferramenta. Mas quando o admin novo olha para a tela e não encontra onde gerenciar nada, o que ele conclui? "Esse sistema é limitado." Você está sentando em cima de um ativo de retenção e não está capitalizando nele porque escondeu.

Primeira prioridade: coloque o controle de admin onde o olho vai naturalmente. Não precisa de refatoração gigante. Uma seção fixa na sidebar — separada visualmente dos itens do app atual — com label "Workspace" ou "Admin", visível apenas para admins, com links diretos para Usuários, Apps e Permissões. Dois itens. Um separador visual. Feito. O usuário que precisa gerenciar o sistema encontra em um segundo. Se você quiser ir além, adicione um badge numérico quando houver itens pendentes de configuração. Mas comece pelo básico: torne o evidente visível.
