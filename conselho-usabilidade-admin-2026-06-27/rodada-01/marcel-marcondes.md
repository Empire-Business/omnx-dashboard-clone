# Marcel Marcondes — Rodada 1: Diagnóstico

Vamos olhar os dados de usabilidade antes de qualquer coisa: um painel de controle crítico que requer 3 passos de descoberta não está com problema de design — está com problema de arquitetura de informação. A causa raiz, do ponto de vista de gestão de produto, é que não existe uma hierarquia clara entre os papéis de usuário na interface. O sistema trata o admin que está operando (vendo métricas, leads) e o admin que está governando (configurando apps, permissões) como se fossem a mesma jornada. Não são. Duas jornadas distintas precisam de entradas distintas.

A maior oportunidade sendo perdida aqui é de produto: um sistema com controle granular de apps por workspace é uma feature de retenção e expansão. Em SaaS B2B, o admin é o decision maker que renova o contrato, aprova upgrades e indica o produto para outros gestores. Se a experiência do admin é frustrante, você está comprometendo exatamente o usuário que mais importa para o negócio. A métrica que move a agulha aqui não é tempo médio de sessão — é "tempo do admin até primeira configuração de workspace." Se essa métrica for alta, churn vai ser alto.

O framework que eu aplicaria: estabeleça dois níveis claros na interface — nível Operação (o que o usuário vê no dia a dia, filtros, apps, dados) e nível Administração (configuração de workspace, apps ativos, permissões, usuários). O nível Administração precisa de uma entrada fixa e óbvia no header, separada da navegação operacional. Um ícone de engrenagem com label "Admin" ou "Workspace" no header, visível apenas para admins, com acesso direto ao painel `/admin`. Simples, auditável, escalável. Qual é a métrica de sucesso? Admin configura o workspace sem contato com suporte na primeira sessão.
